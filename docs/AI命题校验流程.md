# AI 命题校验流程

命题不设置轮数和总时长上限；单次模型请求及程序执行仍有超时保护，任意阶段均可中断。模型调用及自动修订用量累计显示。

输入失败定位使用 `samples/testcases` 集合名及从 1 开始的位置，避免把合并后的测试编号误当成原数组下标。输入修复阶段只允许修改失败位置，不能删减测试或重写参考解答；无实际变化的补丁会返回明确原因供下一次修复。

针对 ADD/DEL/ASK/COUNT 操作流，校验器报告条数或首行错误时，系统在能够完整解析并确认操作合法的前提下，根据真实操作序列重算 q、规范首行，并重新执行全部校验。此操作不修改任何道路操作；其他输入格式不会套用这条规则。重复 ADD 编号不会被静默改号，而是交由结构化操作补丁重新构造，后端计算条数并检查道路生命周期。

题面规范相同时复用审核程序。明确带 `INVALID:` 的输入拒绝异常归入输入错误；校验器自身的格式或执行错误只触发审核程序修订，将原审核代码和具体错误反馈给审核请求。两份解答出现分歧时会丢弃缓存重新核查。

1. 生成题面、样例、测试点和参考解答，严格检查 JSON 字段。
2. 按参考语言实际编译、运行参考解答。Python 与 C++14 分别使用对应执行器。
3. 另行调用模型生成 Python 输入校验器和第二份解答。此次请求只提供题面、规范、少量输入示例及输入规模，不传参考代码和标准输出。
4. 在有时间、内存和输出限制的执行器中，校验所有样例和测试点的输入合法性，并运行第二份解答。
5. 比较两份解答的真实输出。输入合法且两份输出一致时，可以修正模型写错的标准输出；不一致时返回两边输出供定位，不能仅根据参考程序覆盖答案。
6. 修订使用 JSON 字段补丁：编译错误优先修改代码；输入错误优先调用模型生成数据构造脚本、本地执行后用 case_updates 精准修正非法测试点，脚本失败则退回常规修订。普通题目 API 仍严格校验完整配置。

最终结果提供校验程序、第二份解答、修正答案数量及校验说明，可在前端展开审阅。

两份程序来自同一模型的不同请求，并非形式化证明。输入校验器和第二份解答也可能出错；程序超时或分歧会阻止发布。复杂题的独立算法须适合实际输入规模（每测试点 5 秒、256 MB）；本流程不会自动将超时视作通过，也不会降低题目自身资源限制。知识点、样例解释、覆盖面和复杂度区分仍需人工审阅。

测试使用模拟模型响应与真实程序执行，覆盖错误答案自动修正、非法输入拒绝、数据构造脚本修复、参考程序与错误答案同时有误、字段补丁、C++ 编译修订、流式用量及中断，不依赖真实模型付费调用。通过这些测试不等于测得真实模型的成功率。
