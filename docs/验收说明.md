# OJ 系统验收说明

本文按课程实验 Step 1-6 和 Advance AI 的要求记录当前实现、验证方式和已知边界。

## 运行环境

- Python 3.10+
- `g++` 9+（验证 C++ 评测时需要）
- Docker 为可选隔离执行器

安装依赖并运行测试：

```bash
pip install -r requirements.txt
python -m pytest -q
ruff check .
```

启动应用：

```bash
python run.py
```

前端默认地址为 `http://127.0.0.1:8501`，后端默认地址为 `http://127.0.0.1:8001`。

## 关键验收点

### 异步接口

所有 FastAPI 路由均使用 `async def`。测试会检查路由端点是否为协程函数，并使用异步 HTTP 客户端调用接口。

### 评测安全边界

语言注册不接受任意 shell 命令，只允许 Python、`g++`、`clang++` 和受限编译参数。评测进程使用隔离环境变量、输出上限、超时和内存监控；Linux 使用资源限制，Windows 使用 Job Object，Docker 模式使用无网络、非 root 和只读根文件系统。

这意味着当前动态语言注册是“受限语言模板变体注册”，不是任意解释器执行入口。课程要求的 Python 与 C++ 已覆盖；扩展其他语言时应先加入显式白名单和对应执行器测试。

### AI 任务

AI 任务不会直接写入题库。生成结果必须通过题目结构校验、至少 8 组测试输入和参考答案评测，然后送入题目编辑器，由用户审阅后保存。自动测试使用 Mock SSE 服务，不替代真实模型服务的质量评审。

## 已知边界

- Windows Job Object 和 Docker 需要对应平台/软件环境，默认测试环境不可用时不会伪造通过。
- 本地执行器适合课程实验，不是面向公网的不可信代码沙箱。
- SQLite 和单进程后台队列适合课程规模，多实例部署需要独立队列和执行器。
- AI 真实提供商的响应格式和题目质量仍需使用实际配置进行人工验收。
